## 0. 用語と記法

- T: 評価日（営業日）。すべての量は T の引けまでのデータで計算する
- k: スイング確定ラグ（本数）。既定 3
- SMA_n: 終値の単純移動平均。使う n は 5 / 25 / 75 / 200 のみ
- ATR: Wilder の 14 日 ATR。TR = max(H−L, |H−C_prev|, |L−C_prev|)
- 週足: 金曜終わりの週（W-FRI）に集約。T を含む週は未確定として使わない
- ↑ 大きいほど良い、↓ 小さいほど良い、∩ 適正帯 [a, b] がある
- 「銘柄×日」: 1 銘柄の 1 評価日を 1 観測とする
- **F 除外**: R1 で導入した除外フィルタ（§6.1）。候補集合を絞る働きだけを持ち、順位を作らない
- **pctl_pool(x)**: 直近 20 営業日プール（§6.3）における x の百分位（0〜1）

## 0.1 R1 改訂の要旨（実装者はここを先に読む）

検証 L1（148 検定・ホールドアウト未使用）で、総合スコア V1〜V3 の日次 IC が負に有意
（score_v1: IC = −0.0176、NW t = −2.44）となり、分位曲線が完全に逆行した
（最低分位 +0.257% → 最高分位 −0.030%、h=10 超過リターン）。撤退基準 §10.3 の第1項に該当する。

診断は次の3点。**改訂はこの3点にのみ対応し、それ以外は変えない。**

1. **順位付けの符号が RESEARCH.md §1.3 と逆だった。** RESEARCH.md は「スコアの主軸は中期の
   勝ち組の中の短期の負け組であるべき」と結論していたが、R0 §5 は D1（トレンド品質）5 個と
   D2（相対力）3 個をすべて ↑ 方向で採点し、§6.3 で全次元を等加重にしていた。L1 の実測は
   文献側と一致する（d1_ma_stack 最下位分位 +0.254% → 最上位分位 +0.012%、
   d1_slope75 +0.224% → −0.112%、d2_rs60 最上位分位 −0.768%、d2_rs120 最上位分位 −0.635%）。
   **トレンドと相対力はゲート（G1〜G3）で担保する量であって、ゲート内でさらに強い方を選ぶと
   逆効果になる。** これは曲線への後付けではなく、RESEARCH.md の結論の実装漏れの修正である。
2. **目的関数が成功率に寄っていた。** R0 §9 は「評価は成功率より超過リターンと MFE/MAE を
   主にする」と明記していたが、R0 §10.2 の手順は h=10 の超過リターンと成功率しか要求せず、
   MFE/MAE の表が L1 レポートに存在しない。スコア設計側も D6（再上昇トリガー）を必須に
   していたため、成功率は上がるがリターンが下がる方向に最適化されていた
   （d6_trig_a: 発火 True で成功率 0.456→0.587、超過リターン +0.181%→+0.093%。
   d6_break_r も同型）。
3. **効いているのは「中央が良い」ではなく「端が悪い」。** 39 特徴量の 10 分位曲線を見ると、
   超過リターンの情報のほとんどは末端分位が負であることに集中しており、中央部はおおむね平坦
   （+0.10%〜+0.30%）である。連続スコアで順位を作るという前提そのものが実測と合っていない。

したがって R1 は「**除外して等加重で並べる**」構造に変える。押し目状態そのものに価値がある
ことが確認済みのため（(c) 押し目等加重 +0.125% vs (a) SMA200 ランダム −0.025%）、
壊れている順位付けだけを差し替える。

**新規特徴量は 1 つも追加しない。** 39 特徴量の ID・式・計算はすべて据え置く。変えるのは
「どれをどの向きで使うか」と「どう合成するか」だけであり、既存 replay データ（362,461 行）
の再生成は不要で、再集計のみで評価できる。

## 3. スイング検出（fractal・確定ラグ付き）

- スイング高値: High[i] ≥ max(High[i−k..i−1]) かつ High[i] > max(High[i+1..i+k])
- スイング安値: Low[i] ≤ min(Low[i−k..i−1]) かつ Low[i] < min(Low[i+1..i+k])
- 確定: インデックス i のスイングは i+k の引けで確定する。T で使えるのは i ≤ T−k のもののみ
- 交互化: 時間順に走査し、高値が連続したら高い方を、安値が連続したら低い方を残す
  （後から来た方が極端なら置き換える）
  * 交互化は、T 時点で確定済み（i ≤ T−k）の生スイング集合に対して毎回適用する。T が進むと
    末尾の1要素が置き換わることがあるが、これは新たに確定した情報による更新であり未来参照
    ではない。置換は末尾要素にのみ起こる（i1 < i2 の間にある反対側のスイングは i2 より先に
    確定するため）
  * 同値の扱い: 生検出では右側が厳密不等号のため、k 本以内の同値高値（安値）は後の方が
    スイングになる。交互化での同値は先に来た方を残す（置換は厳密に極端な場合のみ）
- ZigZag は使わない（確定ラグが不定で未来参照になる）

実装上の必須テスト: §11 参照。**R1 では変更なし。** 西村ルールの較正（勝率 57.2% / PF 1.24 /
平均保有 4.71 日、出典は 62.7% / 1.59）が方向性を再現しており、スイング検出・時点整合・
ラベル生成の経路は正常に動作していると判断する。

## 4. 押し目の構造と状態

### 4.1 構造（T 時点）

- H0: 確定済みスイング高値のうち最新（インデックス h0 ≤ T−k）。かつ H0 は直前 60 本の最高値
- L0: h0 より前の直近の確定スイング安値（無ければ構造なし）
- 上昇脚: leg = H0.high − L0.low、leg_bars = h0 − l0 ≥ 3
- 押し目区間: h0+1 .. T、日数 d = T − h0
- 押し安値: Lp = min(Low[h0+1..T])、その位置 lp
- 戻り高値 R: lp < T−1 のとき R = max(High[lp+1..T−1])。無ければ欠損
- 基本量（すべて連続値）
  * depth_pct = (H0.high − Lp) / H0.high
  * depth_atr = (H0.high − Lp) / ATR[h0]
  * retrace = (H0.high − Lp) / leg
  * position = (Close[T] − Lp) / (H0.high − Lp)
  * dev5 = Close[T] / SMA5[T] − 1

### 4.2 押し目であるための条件

- 2 ≤ d ≤ 25
- Lp > L0.low（前の押し安値を割っていない）
- max(High[h0+1..T]) < H0.high（H0 未更新）
- depth_pct ≤ 0.25
- Close[T] ≥ SMA200[T]（G2 と同じ。失効判定にも使う）

**R1 での扱い: 変更なし。** R0 §4.4 にあった「浅押し（depth_pct < 3%）は候補に出さない」
「深押し（depth_pct > 10%）は d3_bad_news = 0 のときのみ候補」の 2 条件は、§6.1 の F1・F2 に
統合して削除する（同じことを二重に書かない）。

### 4.3 反発トリガー（日 t で評価）

- trig_a: Close[t] > High[t−1] かつ Close[t] > SMA5[t]
- trig_b: SMA5[t] > SMA5[t−1] かつ SMA5[t−1] ≤ SMA5[t−2] かつ Close[t] > SMA5[t]
- トリガー発火 = trig_a または trig_b

**R1 での扱い: 計算は残すが、候補条件からもスコアからも外す（§6.2）。**
表示と集計切り口としてのみ使う。

### 4.4 状態（毎日ちょうど一つ）

| 状態 | 定義 |
| --- | --- |
| 完了 | High[T] > H0.high（または Close[T] > H0.high）。候補から外す。検証では成功として記録 |
| 失効 | 4.2 のいずれかを満たさない |
| ブレイク | 4.2 を満たし、R が存在し、Close[T] > R |
| 反発開始 | 4.2 を満たし、t_trig ∈ {T−2, T−1, T} にトリガー発火があり、lp ≤ t_trig |
| 形成中 | 4.2 を満たし、上記のいずれでもない |

**R1 での変更: 候補は状態を問わない。** R0 §8.2 は候補を「反発開始・ブレイク」に限定して
いたが、この限定こそが D6 と同じ「成功率は上がるがリターンが下がる」方向の制約であり、
かつ形成中（n=195,804）は 3 状態で最大の観測数を持つ。R1 では 形成中 / 反発開始 / ブレイク
のすべてを候補集合の母集団とし、F 除外だけで絞る。状態は表示と集計切り口として残す。

表示用の参照値: 押し安値 = Lp（構造ストップ参考）、ブレイク参照 = R（無ければ H0.high）

## 5. 特徴量

共通ルール

- T までのデータのみ。スイング由来の量は確定済みスイングのみ。週足は確定週のみ
- 欠損は「欠損」として保持する。**R1 では「欠損 → 0.5 に置く」をやめる**（§6.4）
- **特徴量の ID・式は R1 で一切変更しない。** 変えるのは「用途」列だけである
- **指数（IDX）の日付整列（2026-08-26 追加。データ規約の記録であり見直しではない）**:
  D2（§5 D2）が参照する指数は、銘柄の日付に整列した上で、欠損を最大3営業日まで
  過去方向にのみ前方補完する。3営業日を超える欠損は補完せずそのまま欠損とする。
  未来の値は一切参照しない

用途の記号:
- **F**: §6.1 の除外フィルタに使う（末端分位のみ）
- **S**: §6.4 の順位スコアに使う
- **—**: 計算・保存・表示・集計はするが、候補選択と順位には使わない（診断）

## 9. ラベルと評価指標（検証用）

### 9.1 ラベル

- エントリー: Open[T+1]。h ∈ {3, 5, 10, 15, 20, 30}
- 超過リターン: r_h = ln(Close[T+h]/Open[T+1]) − ユニバース等加重の同じ量
- 成功/失敗/未決（N=15 主、10 と 20 を感度）: T+1 から T+N の各日で、High > H0.high なら成功、
  Low < Lp なら失敗。同日に両方なら失敗（保守的）。N 日以内にどちらも無ければ未決
- MFE = (max(High[T+1..T+N]) − Open[T+1])/ATR[T]、MAE = (Open[T+1] − min(Low[T+1..T+N]))/ATR[T]
- MFE/MAE は判定確定後も打ち切らない固定 N 日窓で測る。L2 の売買シミュレーション（ストップ・
  利確で打ち切る）とは目的が異なる。両者を同じ指標として比較しないこと
- ギャップの扱い: L1 の成功/失敗判定は High/Low のみで行う。L2 では Open < Lp で寄り付いた
  場合の約定価格は Open とし、L1 の判定と L2 の損益が一致しないことを前提とする

**ラベルの計算は R1 で変更しない。** 既存 replay データをそのまま使える。

### 9.2 主指標と従指標（R1 で明確化）

R0 §9 の末尾に「評価は成功率より超過リターンと MFE/MAE を主にする」と書いてありながら
R0 §10.2 が成功率と h=10 だけを要求していた矛盾を解消する。

| 区分 | 指標 |
| --- | --- |
| **主** | 超過リターン r_h の平均（h は §10.1 で選択）、MFE/ATR の平均、MAE/ATR の平均、MFE/MAE 比 |
| **従** | 正の超過リターンの比率、r_h の中央値 |
| **診断（判定に使わない）** | 成功率（H0 更新 / Lp 割れ）、成功までの日数 |

成功率は L1 の判定基準から外す。「H0 を超えるか」は値幅を伴わない到達判定であり、
L1 の実測でリターンと逆相関することが確認されたため、以後は診断としてのみ集計する。

**MFE/MAE の表は必須である。** L1 レポート（T-405）に MFE/MAE の集計が含まれていなかった
ことが、この矛盾を発見できなかった直接の原因である。R1 の再集計では、分位別・F 通過別・
状態別・深さ帯別の MFE/ATR と MAE/ATR を必ず出す。

### 9.3 保有期間 h の選択（SPEC の事前登録に従う）

SPEC.md は「保有期間は固定しない。3/5/10/15/20/30 営業日の先行リターンで決める」と
事前登録している。L1 レポートは h=10 のみを集計したが、これは設計上の決定ではなく
実装上の既定値だった。

- 全 h について §10.2 の主指標を集計する
- **h は §10.1 の設計窓（前半）だけで選ぶ。** 選択基準は「(c) − (a′) が最大になる h」
  （＝押し目状態そのもののエッジが最も明瞭に出る保有期間）
- 参考: 西村ルールの較正（T-404）は平均保有 4.71 日で PF 1.24 を再現している。

  事前に固定はしない

> 頑健性窓の開始日 = 「store 最古日から 272 営業日後の翌営業日」と「2017-03-01」の
> いずれか遅い方

この規則は結果を見て決めたものではなく、以下の制約から導かれる（事後的なデータ拾い食いを
防ぐため、規則は本書に固定し、以後の変更は行わない）。

- **backfill は延長しない。** SPEC.md §4 は「過去データが予告なく書き換わる」ことを明記している。
  backfill は取得時点からの相対日数（period=Nd）で取得するため、開始日をさらに過去に伸ばすには
  全銘柄の再取得が必要になり、既に生成済みの主評価窓 362,461 行の基礎データが変わるリスクを
  背負う。R1 の前提（「主評価窓は再集計のみで足り、再生成は不要」）が崩れるため、この経路は取らない
- **`MIN_HISTORY_BARS=250` は変更しない。** 窓ごとにユニバース定義を変えると主評価窓との
  比較可能性が失われ、§10.3 第 2 関門の G3（設計窓の効果量の 1/2 以上）が計算不能になる
- **`MAX_EMPTY_DAY_RATE` ガードは緩和しない。** データ不足で発火するのはガードの正しい
  挙動であり、境界的な結果が出てもデータを足しに行かない。規則適用後もガードが発火する
  場合は、実装側で回避策を選ばず、TASKS.md の質問ログに追記して止まる
  （「境界的な結果が出てもデータを足しに行かない」の徹底）

## 11. ルックアヘッドの機械的検査（必須テスト）

「全期間で計算して T 行を取り出す」とは、各 T について T までのデータで計算する
（ローリング）ことを指す。一括計算して行を取り出すことではない。

- 再計算一致: 系列を T で切って計算した特徴量 = 全期間で計算して T 行を取り出した特徴量。
  全特徴量・複数 T で完全一致（浮動小数の許容 1e-9）
- スイング（生検出、交互化前）: 「T で切った系列の検出結果」＝「全期間の検出結果を i ≤ T−k で
  絞ったもの」。右端の未確定バー（i > T−k）をスイングとして扱わないこと
- スイング（交互化）: 「T で切った系列で生検出→交互化した結果」＝「T−1 時点の交互化結果に、
  T で新たに確定した生スイングを時間順に逐次適用した結果」
- 週足: T を含む週の足が使われていないこと
- ラベル: T+1 以降のデータだけを使い、T 以前の行を変えても値が変わらないこと
- **R1 追加**: F の分位境界がプール（直近 20 営業日・T を含む）だけから計算されており、
  将来の分布を参照していないこと。設計窓で確定した絶対値を焼き付けていないこと
