# TASKS.md — 作業分割と受け入れ条件

対応文書: SPEC.md（決定）、DESIGN.md（設計）、CLAUDE.md（作業規約）
順番: M1 更新 → M2 → M3a → M4-L1 → **判定（Fable）** → M3b → M4-L2 → M5
L1 の判定が出るまで M3b（表示・テンプレート校正）と M5（描画・配信）には着手しない。

各タスクの完了条件は「受け入れ条件をすべて満たし、必須テストが通り、`python -m unittest discover -s tests -t .` が全件 OK」。
判断が必要な箇所（DESIGN.md に書いていない閾値・方式）は実装せず、質問として TASKS.md 末尾の「質問ログ」に追記して止まる。

## M1 データ基盤（実装済み。設計に合わせて更新）

### T-101 設定と索引の追加
- 目的: DESIGN.md §12 のパラメータを `config.py` に追加（k, pullback_max_days, pullback_max_depth, shallow_depth, deep_depth, pool_days, sector_cap, corr_threshold, top_n, label_n）
- 受け入れ: 環境変数で上書きでき、既定値が §12 と一致。`Settings.from_env()` のテスト追加

### T-102 指数データ
- 目的: TOPIX（`^TPX`、失敗時 `^N225`）の日足を取得し store に `ticker="__IDX__"` として保存。DRYRUN は合成
- 受け入れ: `fetch_index()` が 300 本以上返す。D2 と地合いゲージが参照できる
- テスト: 合成指数で RS 計算が再現一致テストを通る

### T-103 バックフィル（検証用 10 年）
- 目的: `python -m stockbot.cli backfill` で `HISTORY_DAYS=2600` 相当を取得し store に保存。通常の daily とは別コマンド。締切ガードと中断再開（store に既にある銘柄はスキップ）
- 受け入れ: 中断後に再実行すると残りだけ取得する。取得率が fetch_meta に記録される

### T-104 参照データの取得経路（調査込み）
- 目的: JPX の決算発表予定日・上場廃止銘柄一覧を自動取得する。まず JPX 公開ページの URL と書式を調べ、取れるなら `jpx_lists.py` に追加、取れなければ現行の CSV 手動運用のままとし、調査結果を `docs/DATA_SOURCES.md` に書く
- 受け入れ: 取得できた場合、`load_earnings_schedule` / `load_delistings` が同じ列で読める。規約上の制約を明記
- 注意: 取得の可否が分からない場合は実装を止めて質問ログへ

## M2 特徴量

### T-201 指標
- 目的: `features/indicators.py`: SMA(5/25/75/200)、Wilder ATR14、TR、単純 ATR5/ATR20、BB 幅、週足集約（W-FRI、確定週のみ）
- 受け入れ: 既知の小さな系列で手計算と一致。週足集約で T を含む週が除外される
- 必須テスト: 再計算一致（DESIGN.md §11）を各指標に適用

### T-202 スイング検出
- 目的: `features/swings.py`: DESIGN.md §3 の fractal 検出、確定ラグ、交互化。戻り値はインデックス・種別・値・確定インデックスの表
- 受け入れ: 合成系列で期待どおりのスイングが出る。交互化で同種連続が残らない
- 必須テスト: (1) T で切った検出 = 全期間検出を i ≤ T−k で絞ったもの、(2) i > T−k のスイングが含まれない

### T-203 押し目構造と状態
- 目的: `features/pullback.py`: DESIGN.md §4 の H0/L0/Lp/R と基本量、トリガー、状態（完了/失効/ブレイク/反発開始/形成中）、浅押し・深押しフラグ
- 受け入れ: 合成「pullback」系列で 形成中 → 反発開始 → 完了 の順に状態が遷移する。失効条件が各々単独で効く
- 必須テスト: 状態が毎日ちょうど一つ。再計算一致。Lp ≤ L0.low で失効

### T-204 特徴量 D1〜D8
- 目的: `features/dimensions.py`: DESIGN.md §5 の全特徴量を、ID・値・方向・暫定帯・次元のメタデータ付きで返す。欠損は NaN
- 受け入れ: 全 ID が DESIGN.md の表と一致（テストで ID 集合を比較）。形成中では D6 が欠損
- 必須テスト: 再計算一致（全特徴量・複数 T）。欠損数のカウント

### T-205 再計算一致テストハーネス
- 目的: `tests/test_lookahead.py`: 任意の特徴量関数に対して「T で切る／全期間から取り出す」を比較する共通ハーネス。合成 10 銘柄 × T 5 点
- 受け入れ: 新しい特徴量を追加したら自動的に対象に入る（メタデータから列挙）

### T-206 日次特徴量の保存
- 目的: `daily/features_YYYY-MM-DD.csv.gz` に全採点銘柄の特徴量・状態・次元スコア・総合スコア・地合いを保存（前向き検証用）
- 受け入れ: 列名が安定し、後日 resolver（T-504）が読める

### T-207 地合いゲージとブレス
- 目的: DESIGN.md §8.1 の 6 点ゲージ。指数と store 全体から計算
- 受け入れ: 合成データで 強/中/弱 が出る。再計算一致

## M4-L1 検証レイヤー 1

### T-401 ラベル
- 目的: `validation/labels.py`: DESIGN.md §9。超過リターン h ∈ {3,5,10,15,20,30}、成功/失敗/未決（N=10/15/20）、MFE/MAE
- 受け入れ: 手計算の小例と一致。同日に H0 超えと Lp 割れがある日は失敗
- 必須テスト: T 以前の行を変えてもラベルが変わらない

### T-402 歴史的再生（リプレイ）
- 目的: `validation/replay.py`: 主評価窓・頑健性窓の各営業日 T について、T で切った系列から M2/M3a を走らせ、銘柄×日の特徴量・スコア・状態・ラベルを 1 つの表に蓄積（parquet/csv.gz）。ホールドアウトは生成しない（フラグで明示的に有効化）
- 受け入れ: 1 年分の再生が所要時間とともにログされ、中断再開できる。ユニバースは T 時点で履歴 250 本以上の銘柄
- 必須テスト: 再生の 1 日分 = 日次パイプラインを同じ T で走らせた結果（同一性）

### T-403 L1 集計
- 目的: `validation/layer1.py`: DESIGN.md §10.2 の 0〜6。相関行列、単変量 10 分位曲線、次元 IC（日次 Spearman → 平均・NW t）、総合 V1/V2/V3 の IC・分位曲線・成功率、切り口別（状態・地合い・深さ帯・年・市場区分・月）、ベースライン (a)(b)(c)、検定数ログ、BH-FDR、生存バイアス上限
- 受け入れ: すべての表が csv と markdown で出る。検定数が自動で数えられる
- 注意: 閾値の解釈や採否の判断はしない。表を出すだけ

### T-404 西村ルールの再現(較正)
- 目的: DESIGN.md §10.2 (b) のルールをそのまま売買シミュレーションし、2016〜2020 の勝率・平均損益・PF・平均保有を出す
- 受け入れ: 結果が `validation/reports/calibration_nishimura.md` に出る。期待値（勝率 60% 前後、PF 1.5 前後）との差を数値で併記（解釈はしない）

### T-405 L1 レポート
- 目的: `validation/report.py`: T-403 の表と図（分位曲線、IC 時系列、地合い別）を 1 つの markdown に束ねる。冒頭に「検定数」「ホールドアウト未使用」を明記
- 受け入れ: Fable がこのレポートだけで判定できる（DESIGN.md §10.3 の項目がすべて載っている）
