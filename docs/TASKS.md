# TASKS.md — 作業分割と受け入れ条件

対応文書: SPEC.md（決定）、DESIGN.md（設計）、CLAUDE.md（作業規約）
順番: M1 更新 → M2 → M3a → M4-L1 → **判定（Fable）** → M3b → M4-L2 → M5
L1 の判定が出るまで M3b（表示・テンプレート校正）と M5（描画・配信）には着手しない。

各タスクの完了条件は「受け入れ条件をすべて満たし、必須テストが通り、`python -m unittest discover -s tests -t .` が全件 OK」。
判断が必要な箇所（DESIGN.md に書いていない閾値・方式）は実装せず、質問として TASKS.md 末尾の「質問ログ」に追記して止まる。

## M2 特徴量

### T-201 指標
- 目的: `features/indicators.py`: SMA(5/25/75/200)、Wilder ATR14、TR、単純 ATR5/ATR20、BB 幅、週足集約（W-FRI、確定週のみ）
- 受け入れ: 既知の小さな系列で手計算と一致。週足集約で T を含む週が除外される
- 必須テスト: 再計算一致（DESIGN.md §11）を各指標に適用

### T-202 スイング検出
- 目的: `features/swings.py`: DESIGN.md §3 の fractal 検出、確定ラグ、交互化。戻り値はインデックス・種別・値・確定インデックスの表
- 受け入れ: 合成系列で期待どおりのスイングが出る。交互化で同種連続が残らない
- 必須テスト: (1) T で切った検出 = 全期間検出を i ≤ T−k で絞ったもの、(2) i > T−k のスイングが含まれない

### T-203 押し目構造と状態
- 目的: `features/pullback.py`: DESIGN.md §4 の H0/L0/Lp/R と基本量、トリガー、状態（完了/失効/ブレイク/反発開始/形成中）、浅押し・深押しフラグ
- 受け入れ: 合成「pullback」系列で 形成中 → 反発開始 → 完了 の順に状態が遷移する。失効条件が各々単独で効く
- 必須テスト: 状態が毎日ちょうど一つ。再計算一致。Lp ≤ L0.low で失効

### T-204 特徴量 D1〜D8
- 目的: `features/dimensions.py`: DESIGN.md §5 の全特徴量を、ID・値・方向・暫定帯・次元のメタデータ付きで返す。欠損は NaN
- 受け入れ: 全 ID が DESIGN.md の表と一致（テストで ID 集合を比較）。形成中では D6 が欠損
- 必須テスト: 再計算一致（全特徴量・複数 T）。欠損数のカウント

### T-205 再計算一致テストハーネス
- 目的: `tests/test_lookahead.py`: 任意の特徴量関数に対して「T で切る／全期間から取り出す」を比較する共通ハーネス。合成 10 銘柄 × T 5 点
- 受け入れ: 新しい特徴量を追加したら自動的に対象に入る（メタデータから列挙）

### T-206 日次特徴量の保存
- 目的: `daily/features_YYYY-MM-DD.csv.gz` に全採点銘柄の特徴量・状態・次元スコア・総合スコア・地合いを保存（前向き検証用）
- 受け入れ: 列名が安定し、後日 resolver（T-504）が読める

### T-207 地合いゲージとブレス
- 目的: DESIGN.md §8.1 の 6 点ゲージ。指数と store 全体から計算
- 受け入れ: 合成データで 強/中/弱 が出る。再計算一致

### T-208 ゲート G0〜G3
- 目的: `features/gates.py`: DESIGN.md §2 の 4 ゲートを判定する
  - G0: ユニバース通過（universe/latest.csv の passes）、かつ T から label_n 営業日以内に
    決算発表が無い（earnings_schedule が空、または当該銘柄の予定日が取れない場合は
    この条件を省略して True とし、`g0_earnings_unknown = True` を立てる）
  - G1: SMA75[T] > SMA200[T] かつ SMA200[T] > SMA200[T-30]
  - G2: Close[T] >= SMA200[T]
  - G3: Close[T] >= 0.75 * max(High[T-251..T])
- 戻り値: 各ゲートの bool と総合 `gate_pass`、および g0_earnings_unknown
- pipeline.py: 採点対象を「gate_pass かつ 状態が形成中/反発開始/ブレイク」に変更する。
  日次特徴量ファイルには gate 列も保存し、ゲート落ちの内訳がログに出るようにする
  （G1 落ち / G2 落ち / G3 落ち / 決算接近 の件数）
- 受け入れ: 合成データで各ゲートが単独で効く。決算データが無い場合も落ちない
- 必須テスト: 再計算一致（DESIGN.md §11）。SMA200[T-30] の履歴が足りない日は False
