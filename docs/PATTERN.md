## 1. 事前登録したパラメータ（検出数を見る前に固定）

**検出数を見てから動かさない。** 動かし始めると、検出数を見ながら形を作ることになる
（設計責任者の明示指示）。

**出典の有無を列に持つ。** 文献値は出典のとおり、裁量値は「文献に数値が無いことを
確認したうえで決めた」ことを明示する。あとから「これは根拠のある数字だったか」を
引けるようにするため。裁量値であること自体は問題ではない —— **裁量値を文献値のように
扱うことが問題**である。

| 記号 | 値 | 出典 | 何に使うか |
| --- | --- | --- | --- |
| **等値とみなす幅** | **±1.5%** | 文献値（LMW 2000） | 2 つ以上の極値が「同じ高さ」かの判定 |
| **ボックスの水平許容** | **±0.75%** | 文献値（LMW 2000） | 上辺・下辺それぞれの点が平均から離れてよい幅 |
| **ダブルボトムの最小間隔** | **22 営業日** | 文献値（LMW 2000） | 2 つの安値の距離。上限はウィンドウが兼ねる |
| **探索ウィンドウ** | **63 営業日** | 文献値（Savin-Weller-Zvingelis 2007。Bulkowski の H&S 平均完成期間に基づく） | 全極値がこの範囲に収まること。**全パターン共通** |
| **タッチ点数** | **3 + 2（最小 5）** | 文献値 | 回帰で 2 本の線を引くときの各辺の点数 |
| **フラッグ／ペナントの上限** | **15 営業日** | 文献値 | フラッグは未満、ペナントは以下 |
| **ε（水平とみなす傾き）** | **日次 0.1% 未満** | **裁量値**（文献に数値なしと確認済み） | 水平な上辺・下辺・平行の判定 |
| **旗竿** | **5 営業日以内に 10% 以上の上昇** | **裁量値**（同上） | フラッグ／ペナントの直前の急騰 |
| **トリプル／逆三尊の隣接間隔** | **10 営業日** | **裁量値**（同上） | 隣り合う谷どうしの距離。下限のみ |

**±0.75% は ±1.5% とは別の定数である。** ボックスの辺は「複数点が 1 本の水平線に
乗っている」ことを要求するので、2 点が等値かの判定より狭い。片方を他方から導かない。

**探索ウィンドウは全パターンで 63 営業日に統一する。** 保ち合い系だけ LMW の 38 日に
する案もあるが採らない —— **パターンごとにウィンドウを変えると、あとで「どのウィンドウが
効いたか」を切り分けられなくなる**（設計責任者の判断）。フラッグ・ペナントには 15 営業日の
別の上限があるので、63 日はそれより緩い外枠として働くだけである。

**±1.5% は ATR 連動にしない。** 銘柄のボラティリティで許容幅が変わると、同じ「ダブル
ボトム」が銘柄ごとに別の形を指すことになる。固定率で揃える（設計責任者の判断）。

### 感度分析はしない

**閾値を振って検出数の変化を記録し、ロバストな作動域を選ぶ、ということはしない。**
それは検出数を見ながら閾値を決めることであり、前のプロジェクトで撤退した構造そのもの
である（設計責任者の判断）。

文献（Savin et al.・Cervelló-Royo ほか）がやっているのは**研究としての頑健性検証**で、
ここでやろうとしているのは**運用値の決定**である。目的が違うので手法を借りない。

**閾値は固定したまま、検出数は記録だけする。** 動かすなら、動かす条件を先に決める。

これらを変えるときは §4 の質問ログを通し、**変更前に**決める。検出数を見たあとの変更は
「形を数字に合わせた」ことになるので、記録に残したうえで別物として扱う。

## 2. 対象パターン

**7 パターン。上昇ウェッジは対象外**（2026-09-08 決定）。

### 2.1 反転系（先に実装する）

極値は `swings.py` の**確定済み交互スイング**（`swings_as_of`）だけを使う。
安値と高値が交互に並ぶ列の、末尾側から必要な本数を取る。

#### 共通

| 項目 | 決め方 |
| --- | --- |
| ネックライン | **水平線**。2 点を結ぶ斜めの線は使わない（傾きを許すと許容傾きという新規パラメータが要る。ε を流用すると意味が変わる） |
| 完成 | **終値がネックラインを上抜けた日 T に成立**。極値が揃っただけでは成立させない |
| 確定ラグ | `swings.py` の k=3 だけ。**LMW の確定ラグ 3 本は使わない**（二重にかけると 6 本遅れる） |
| ウィンドウ | 使う極値がすべて T から遡って **63 営業日以内**に収まること（全パターン共通） |

#### R1 ダブルボトム

| | |
| --- | --- |
| 極値 | 安値 L1 → 高値 H → 安値 L2 |
| 等値 | `\|L1 − L2\| / ((L1 + L2) / 2) ≤ 0.015` |
| 間隔 | L1 と L2 が **22 営業日以上**離れる |
| ネックライン | 谷間の高値 H（1 点・水平） |
| 完成 | `終値[T] > H` |

#### R2 トリプルボトム

| | |
| --- | --- |
| 極値 | 安値 L1 → 高値 H1 → 安値 L2 → 高値 H2 → 安値 L3 |
| 等値 | 3 谷の平均 `m = (L1+L2+L3)/3` に対し、**各谷が m の ±1.5% 以内** |
| 間隔 | 隣接する谷（L1-L2・L2-L3）が**それぞれ 10 営業日以上**離れる |
| ネックライン | `max(H1, H2)`（谷間の高値 2 点のうち高いほう・水平） |
| 完成 | `終値[T] > max(H1, H2)` |

#### R3 逆三尊（逆ヘッドアンドショルダー）

| | |
| --- | --- |
| 極値 | 安値 E1（左肩）→ 高値 E2 → 安値 E3（頭）→ 高値 E4 → 安値 E5（右肩） |
| 肩 | E1 と E5 が両者の平均の **±1.5% 以内** |
| ネックライン点 | E2 と E4 が両者の平均の **±1.5% 以内** |
| 頭 | `E3 < E1` かつ `E3 < E5`。**深さの下限は設けない** |
| 間隔 | 隣接する谷（E1-E3・E3-E5）が**それぞれ 10 営業日以上**離れる |
| ネックライン | `max(E2, E4)`（水平） |
| 完成 | `終値[T] > max(E2, E4)` |

**R2 と R3 は別パターン**（D-2）。R2 は 3 谷が等値、R3 は中央が両側より低い。
E3 が 3 谷の平均 ±1.5% に収まりつつ E1・E5 の両方より低いことはありうるので、
**同じ 5 極値が両方に該当する形が出うる。その場合は両方を記録する**（どちらかに寄せない。
どちらの形として出やすいかは、検出数を見てから設計責任者が判断する）。

#### 「形は揃ったがネックライン未抜け」を数える

`detect_patterns(..., include_pending=True)` で、極値の並び・等値・間隔・ウィンドウを
すべて満たすが `終値[T] > ネックライン` だけを満たさない行も返す。`breakout` 列で
区別する。

**成立の定義は変えていない。** 既定では成立した行だけが返り、記録にも配信にも
未抜けの行は使わない。**成立が 0 件だったときに「条件が厳しい」のか「実装が間違って
いる」のかを 1 回で切り分けるためだけのもの**（設計責任者の指示）。

`cli pattern` は 4 つの数字を出す。

| 出す数 | 意味 |
| --- | --- |
| 成立 | ネックラインを上抜け済み |
| 形は揃ったが未抜け | 極値は揃っている。どこで落ちているかの切り分け用 |
| 形も揃わなかった銘柄 | 極値の並び・等値・間隔・ウィンドウのどれかで落ちた |
| 評価銘柄 | 履歴が足りて判定に入った銘柄 |

**成立・未抜けとも、銘柄コードと極値を日付つきで列挙する**（各30件まで、ネックラインに
近い順）。位置（バー番号）ではチャートで探せないので日付に直す。並び順は目視する順番を
決めるだけで、絞り込みでも閾値の判断材料でもない。

```
[pattern] --- 未抜け 11件（ネックラインに近い順）---
[pattern]   1392.T    inverse_hs     終値 2980.7 → ネックライン 3128.6 (+5.0%) / span 41本
[pattern]     谷 07-15 2830.0 / 08-11 2813.8 / 09-07 2870.1
[pattern]     山 07-29 3128.6 / 08-25 3113.5
```

これは **D-4 の「形を目視確認してから」を満たすための出力**である。成立 0 件が続く間も、
未抜けの形をチャートで見て「これをダブルボトムと呼んでよいか」を確かめられる。

読み方の目安（設計責任者の観点）:

- **0 件** → 未抜けの件数を見る。そこも 0 なら形の条件か実装、そこが出ていれば
  上抜け待ちなだけ
- **数百件** → ±1.5% が緩いか、スイング検出が細かい極値を拾いすぎている
- **数件〜数十件** → 想定内

### 2.3 撤退・測定目標・比率

**判定には使わない。** 形の判定を通った行に付ける表示用の量で、条件でも閾値でもない。

| 量 | 決め方 |
| --- | --- |
| 撤退の目安 | **パターンの最安値**（逆三尊なら頭、ダブルボトムなら 2 安値の低いほう） |
| 高さ `h` | ネックライン − 最安値 |
| **測定目標** | **ネックライン + h**（文献上の目安。統計的裏付けは調べていない） |
| 抜け幅 | `終値 / ネックライン − 1`。負なら未抜け |
| `b` | 抜け幅 ÷ 高さ |
| **比率** | `(1 − b) / (1 + b)`。上（目標まで）÷ 下（撤退まで） |
| 損益分岐勝率 | `1 / (1 + 比率)` |

**測定目標は「文献上の目安」と明記して出す。** 押し目型で直近高値を目標にして
「目標が撤退より近い」問題が出たのと同じ轍を踏まないよう、**比率を必ず併記する**。

#### 比率は抜け幅で決まる

代数で決まる。抜けた直後（`b ≈ 0`）なら **比率 ≈ 1.0**、損益分岐勝率 50%。

| `b`（抜け幅÷高さ） | 比率 | 損益分岐勝率 |
| --- | --- | --- |
| 0.00 | 1.00 | 50.0% |
| 0.05 | 0.90 | 52.5% |
| 0.10 | 0.82 | 55.0% |
| 0.20 | 0.67 | 60.0% |

押し目型（直近高値を目標）の中央 0.38・損益分岐 72% とは別物である。

**比率は常に「T の終値で買ったら」の数字である。** 成立行では終値＝上抜け日の終値
なので実際の想定エントリーだが、**未抜け行では「まだ抜けていないのに今買ったら」の
仮定**になる。`b` が負になるぶん比率は 1 を大きく超える（2〜6 になることもある）。
**成立と未抜けの比率を同じ土俵で比べない。**

## 3. 記録

配信記録・結果付けの仕組みは `SCREENER.md` §3 のものをそのまま使う。

### 3.1 記録するのは成立だけ（2026-09-10 決定）

**`delivered_*.csv` に書くのは成立（ネックライン上抜け）した行だけ。監視（未抜け）は
表示のみで、記録しない。**

理由は**単位が違う**こと。

| | 成立 | 監視 |
| --- | --- | --- |
| 性質 | **事象**（抜けた日 1 日） | **状態**（同じ形が何日も続く） |
| 記録したら | 1 形 = 1 レコード | 1 形 = 滞留日数ぶんのレコード |

`outcome_*.csv` は T+1..T+5 の固定 5 本で、**事象にしか付けられない**。監視を記録すると
分母が「形の数」ではなく「形 × 継続日数」になり、**長く滞留した形ほど重く数えられる。**
反転系は滞留が長い（未抜けの形は数日〜数週間そのまま残る）ので、押し目型の連続点灯より
歪みが大きい。

### 3.2 監視の推移は日次スナップショットに残す

記録の単位を変えずに「監視に何日出ていたか」を後から引けるようにする。
`screen_summary_*.json` 相当の日次ファイルに、その日の監視銘柄と `breakout_pct` を
残す。**これは観測値であって台帳ではない**（上書きしてよい・結果付けの対象外）。

### 6.1 構成

**パターン別にセクションを分ける**（2026-09-10 決定）。パターンごとに性格が違うので、
まずパターン別に見えるほうが読みやすい。

各パターンの中を **候補（成立）** と **監視（未抜け）** の 2 つに分ける。

| セクション | 中身 |
| --- | --- |
| 候補（成立） | ネックラインを抜けた銘柄。**記録に残る**（§3.1） |
| 監視（未抜け） | 形は揃っている。ネックラインまでの距離つき。**記録に残さない** |

**監視を出す理由**: 成立は 1 日 1 件あるかないかで、配信がほぼ毎日ゼロになる。
「形は揃った、あとは抜けるだけ」を前日に知っておけるほうが早い。

### 6.2 1枚目のカード（銘柄ごと）

- 銘柄コード・銘柄名・33 業種
- **パターン名**
- 終値とネックライン（保ち合い系は上値抵抗線）、**抜け幅 %**
- **極値の日付と価格** —— チャートで形を確認するため。押し目型と決定的に違う点
- 形成期間（span 何本）
- **撤退の目安**（パターンの最安値）と乖離率
- **測定目標**（文献上の目安と明記）と乖離率、**比率**（§2.3）
- 20 日平均売買代金
- **決算までの日数**

**決算日は 9 割方「未取得」になる。** JPX のカバー率は 2.5〜10.4% で振れる
（`SCREENER_CLOSING.md`）。それでも載せる —— 載せないと、取れている 1 割の情報まで
消える。赤字が並ぶのは実態の表示である。

サマリー。パターン別の件数と銘柄一覧。

### 6.4 業種は並び順に使わない

### Q-1（2026-09-08 提起・2026-09-08 クローズ）7 パターンの判定式

**判定式が手元に無い。** 設計責任者は「今回のレポートで判定式は揃った」としているが、
そのレポートはこのリポジトリにも会話にも入っていない。

リポジトリ内で確認できるのは `docs/RESEARCH.md` §2.1 の 1 行だけで、そこにあるのは
LMW の**方法論**（カーネル平滑化、35 日＋確定用 3 日、条件付き分布 vs 無条件分布）であり、
**パターンごとの判定式でも ±1.5% の出典でもない。**

推測で埋めない（CLAUDE.md）。足りないものを具体的に挙げる。

**反転系 3 つ（先に要るもの）:**

1. **±1.5% を何に当てるか。** ダブルボトムなら 2 つの安値どうし、で読める。
   トリプルボトムは「3 つが互いに ±1.5%」か「1 つ目を基準に各々 ±1.5%」か。
   逆三尊は「両肩どうしが ±1.5%」か、頭の深さにも条件があるか
2. **ネックラインの引き方。** 間の戻り高値 2 点を結ぶか、水平（ε 判定）を要求するか
3. **完成の定義。** ネックライン抜けを待つか、極値が揃った時点で検出とするか。
   LMW はウィンドウ内で完成したものだけを扱い確定ラグ 3 本を置くが、その 3 本を
   ここでも使うか（`swings.py` の確定ラグ k とは別のもの）
4. **探索ウィンドウ。** LMW の 35 日を採るか、別の長さか
5. **極値の間隔。** 2 つの安値が近すぎる／離れすぎている場合の下限・上限

**保ち合い系 4 つ:**

6. **どの 4 つか。** 上昇ウェッジを除いた 7 のうち、反転系 3 つ以外の 4 つの名前

**回答を受けて §2 に展開し、クローズした。** 新しく決まった 4 つの数値（探索ウィンドウ

### D-6（2026-09-09）探索ウィンドウを 63 営業日にし、出典を明示する

**探索ウィンドウを 60 → 63 営業日に変更した。** 根拠は Savin-Weller-Zvingelis (2007) が
反転系に 63 営業日を使い、Bulkowski の H&S 平均完成期間に基づくと明記していること。
**60 日は勘で置いた数字**（D-5 時点の設計責任者の自認）で、同じ水準に根拠のある数字が
あるなら、そちらを採る。**保ち合い系も 63 日で統一する**（パターンごとに変えると、
あとでどのウィンドウが効いたか切り分けられない）。

**この変更は検出数を見る前に決めた。** 変更の根拠は文献であって観測ではない。
実データでの検出はこの時点で 1 度も読んでいない。

§1 のパラメータ表に**出典列**を追加した。ε・旗竿・隣接間隔 10 営業日は、**探した範囲で
文献値が存在しないことを確認したうえでの裁量値**である。裁量値であること自体は問題では
なく、裁量値を文献値のように扱うことが問題なので、区別を表に持たせた。

**感度分析はしない**（§1）。閾値を振って検出数を比較しない。

### D-7（2026-09-10）抜け幅の下限は入れない

**`終値 > ネックライン` のまま、抜け幅の下限は設けない。**

2026-09-10 の初の成立（5202.T・逆三尊）は抜け幅 0.2% で、「抜けたと言えない水準」
という見方はできる。日中の値動きで簡単に戻る。

**しかし下限を入れると比率が削れる。** §2.3 のとおり比率 = `(1 − b) / (1 + b)` なので、
大きく抜けてから買うほど撤退が遠く目標が近くなる（b=0.20 で 0.67）。
**抜け幅が小さいほどリスクリワードは良い。**

つまりこれは「シグナルの確からしさ」と「リスクリワード」のトレードオフであって、
下限を入れれば片方だけ良くなる話ではない。**動かす根拠が無い**ので入れない。

抜け幅の分布は `cli pattern` が日次で出す（下限の判断材料としてではなく、記録として）。

### D-8（2026-09-10）記録は成立のみ・業種は表示のみ・パターン別セクション

- **記録は成立のみ。監視は表示のみ**（§3.1）。状態を事象として記録すると、分母が
  「形の数」ではなく「形 × 継続日数」になる
- **監視の推移は日次スナップショットに残す**（§3.2）。記録の単位を変えずに済む
- **業種は並び順に使わない。表示のみ**（§6.4）
- **配信はパターン別にセクションを分ける**（§6.1）
- **決算日は載せる。** 9 割が「未取得」になる前提（§6.2）
- **測定目標は「文献上の目安」と明記し、撤退との比率を併記する**（§2.3）
