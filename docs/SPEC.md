## 0. 目的

日本株から「上昇トレンドを維持したまま押し目を形成し、再上昇する確度が高い局面」を
チャート形状中心に定量評価し、毎営業日ランキングして LINE に配信する。
再現性（時点復元・ルックアヘッド排除）を最優先とし、優位性が検証できない要素は運用に持ち込まない。

## 2. 前提（違えば訂正する）

- スクリーニングは「監視価値のランキング」を出す層。発注判断は人が行う。
- シグナルは日付 T の引け時点で確定する情報のみで計算し、T+1 朝に配信、行動は T+1 以降。
- スイングポイント（押し安値・直近高値）は確定ラグ k 本（k は設計時に決定）を置いた fractal 方式。ZigZag は確定ラグが不定なので使わない。

## 3. 検証設計

### L1: ファクター型（スコアの予測力）
- 毎営業日の横断面で、スコア分位（10分位）ごとの先行リターン（同日ユニバース等加重を引いた超過）と成功率を集計。
- Spearman IC の時系列と、その平均・t値（日次の系列相関を考慮）。
- 切り口: 年別 / 地合い別（ゲージ3段階） / 深さ帯別 / 市場区分別。
- ベースライン: (a) 200日線上の銘柄をランダムに選ぶ、(b) 「25日線接触＋上昇トレンド」の単純ルール。スコアがこれらに勝てなければ採用しない。
- データスヌーピング対策: 特徴量と仮説を調査フェーズで事前登録してから見る。パラメータは小さなグリッドで「範囲」を評価する。直近6か月はホールドアウトとして触らない。
- 旧 v7.1 の結果（5年・37時点で IC≈0）を反証対象として最初に通す。
- 生存バイアスの上限評価（§4）を全ての集計に併記する。

### L2: トレード型（売買シミュレーション）
- L1 で優位性が確認できた要素だけを使う。
- エントリー A/B、出口 ①②③ の組合せで、勝率・PF・期待値・最大DD・Sharpe・保有日数分布を集計。
- 同日に複数シグナルが出るため、同時保有上限と相関（テーマ集中）の影響を別途集計。

### 前向き検証（主検証の一つ）
- 日次出力（全採点銘柄のスコア・特徴量）を `history/` に日付別ファイルで蓄積し、後日実現リターンと突合する。時点 T の記録は将来の上場廃止に影響されないため、蓄積分は生存バイアスのない検証データになる。旧リポジトリの運用を継続・拡張する。

## 4. データ設計（yfinance のみ）

### ソースと役割
| ソース | 役割 | 制約 |
|---|---|---|
| yfinance | 日足四本値・出来高（ライブと長期履歴）、分割イベント | 非公式・レート制限。上場廃止銘柄のデータなし。決算日・調整係数・ストップ高フラグなし。過去データが予告なく書き換わる |
| JPX 公開リスト | 上場銘柄一覧（ユニバース更新）、決算発表予定日（ライブの決算除外）、上場廃止銘柄一覧（生存バイアスの上限評価） | 現在時点のみ。自動取得の可否と規約は要確認 |

### 受け入れる制約（明文化）
- 過去の検証はすべて「現在生き残っている銘柄」で行う。結果は実力より良く出る方向に偏る。
- 過去時点の上場銘柄集合は復元できない。新規上場は上場日で除外できるが、上場廃止分は欠ける。
- 過去の決算発表日は取れない。検証では決算イベントを事後検出（ギャップ＋出来高急増）で分離する。
- ライブ取得は不安定な前提で、欠損日があっても運用が止まらない設計にする。

### 緩和策
1. 生存バイアスの上限評価: JPX の上場廃止銘柄一覧から、各年に「流動性基準を満たし上昇トレンドにあった」銘柄の廃止件数と理由（TOB・MBO・完全子会社化 / 上場廃止基準・破産）を数える。前者は株主に有利な事象が多く、後者は本戦略の対象（上昇トレンド・流動性あり）では稀。最悪ケースとして「廃止銘柄のトレードは全て損切り」と仮定した下限成績を併記する。
2. 前向き検証を主検証に格上げ: 毎日の全採点銘柄のスコアと特徴量を `history/` に保存し、後日の実現リターンと突合する。6か月で約120営業日分が貯まる。
3. 時点復元の蓄積: 取得した日足、決算発表予定日、上場銘柄一覧を日次スナップショットとして私的に保存し、yfinance の遡及的な書き換えに備える。
4. 評価窓の使い分け: 主評価は直近5年（廃止の累積が少ない）、10年は頑健性の確認。直近6か月はホールドアウト。

### ルール
- 取得は `auto_adjust=False`・`actions=True`。Yahoo の価格は分割調整済み・配当未調整なので自前で係数を掛け直さない（二重調整になる）。分割イベント日に価格が比率どおり跳んでいれば未調整とみなしてイベント前の行を修正し、イベント記録なしに分割比率どおりの価格と出来高の跳びがある銘柄は「未記録分割の疑い」として除外する（M1 `adjust.py`）。
- 配当・権利落ち: 価格調整はしない。権利落ち日のギャップはイベントとして記録し、押し目と誤認しない。
- 欠損: 四本値のいずれかが欠ける行は落とす。履歴250営業日未満の銘柄は採点しない。
- ザラ場中の未確定足は使わない（7:00 JST 実行なら前営業日までが確定）。
- 検証時のユニバース: 現在の上場銘柄から T 以降の新規上場を除外した集合。
- 売買代金は終値×出来高で近似する。

### 取得（ライブ）
- 旧 v7 の取得ループを流用: 100→50→10→1件とチャンクを縮めながら失敗分だけ再取得、締切ガード付き。実績は約97%。
- 流動性フィルタ後の銘柄に絞って取得回数を減らす。増分取得（直近数週間）＋キャッシュ。
- 弾かれ続ける場合の逃げ道: セルフホストランナー or 小型VPS。設計に含める。

## 5. 出力仕様（案・レイアウト確定は実装前に再確認）

### 維持するデザイン要素
背景（hero.jpeg）、マスコット（mascot.png）、ヘッダー帯、日付バッジ、地合いボックス、データ状況ボックス、番号付き候補カード（バッジ・コード・銘柄名・補足行・3つの数値ボックス・右側の説明欄）、監視リスト、免責、2枚目のまとめ画像。

### 中身の置換(案)
- 地合いボックス: TOPIX の 25/75/200 日線位置と傾き、75日線・200日線の上にある銘柄比率、新高値/新安値比率。3段階表示。
- データ状況: 取得率、失敗件数、スナップショットの最終保存日。
- 候補カード: 総合スコアと順位、ステージ（押し目形成中 / 反発開始 / ブレイク）、サブスコア内訳（トレンド / 押し目の形 / 出来高 / 収縮 / 相対力 / 週足）、押しの深さ（% と ATR）と日数、着地した移動平均線、押し安値（構造ストップ参考）と直近高値（ブレイク参照）、決算までの営業日数、20日平均売買代金。
- 監視リスト: スコアは高いが反発未確認、または決算近接で除外された銘柄。
- 価格・株数・損益の計算は載せない（発注判断は人）。

### 描画方式（提案）
HTML/CSS テンプレート（Jinja2）を headless Chromium（Playwright）で PNG 化。理由: 日本語の折返しとカード配置を CSS に任せられ、Pillow で座標を手計算するより保守が楽。Actions での Chromium 導入は1〜2分。Pillow 版は予備。
